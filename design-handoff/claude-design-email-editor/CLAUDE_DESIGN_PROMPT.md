# Nomi Visual Email Editor — Claude Design brief

Use the six attached screenshots as the visual and interaction source of truth. Create a production-grade responsive design for the Nomi Visual Email Editor. This is not a blank template builder: it edits the merchant's existing emails generated by Claude.

## Product goal

Merchants must be able to open any current email, visually edit it, drag and reorder safe blocks, preview it responsively, and save it back to the same flow without breaking email-client compatibility.

## Required screens and states

1. Desktop editor at 1440px or wider.
2. Active drag-and-drop state with an explicit cyan insertion rail.
3. Selected block with a context-sensitive inspector.
4. Layers/reorder mode with locked header and footer.
5. Existing-email picker containing five flows and 13 emails.
6. One-time conversion screen for older HTML-only emails.
7. Desktop and 390px mobile email previews.
8. Mobile Add block sheet, Reorder list, and Inspector sheet.
9. Preview-only mode.
10. Saved, unsaved, saving, validation-error, empty, and loading states.

## Existing email set

- Welcome: 3 emails
- Still Interested?: 2 emails
- Abandoned Cart: 3 emails
- How Was It?: 2 emails
- Welcome Back: 3 emails

Switching an email must update the breadcrumb, canvas content, layers, inspector, and save state. Preserve the selected look, flow, and email when entering the editor.

## Desktop layout

- Top bar: Nomi mark, breadcrumb/current email, saved status, Preview, Save changes.
- Left panel: Blocks/Layers tabs, search, block library, and draggable block cards.
- Center: contained internally scrolling email canvas, 600px desktop or 390px mobile, zoom controls, selection outlines, drop rails.
- Right panel: inspector for the selected block.

Blocks: Heading, rich text, button, image, product, product row, divider, spacer, and two columns.

## Required interactions

- Drag a library block into a valid insertion rail.
- Reorder existing blocks using drag handles.
- Select a block on the canvas.
- Edit copy and settings with immediate canvas updates.
- Duplicate, hide/show, and delete ordinary blocks.
- Protect required preheader, header, footer, legal, and unsubscribe sections.
- Undo inserts, moves, duplicates, hides, and deletes.
- Switch desktop/mobile preview.
- Save changes with visible saved/unsaved feedback.
- Enter and exit clean preview mode.
- Filter the block library with search.

## Existing HTML conversion

Older saved HTML must remain unchanged until the merchant approves conversion. Show:

- Original email preview.
- Detected copy/headings.
- Images and alt text.
- Products and destination links.
- Brand styles.
- Protected footer/legal content.
- Convert and open editor action.
- Original HTML comparison after conversion.

## Visual direction

- Calm, editorial, premium ecommerce-tool aesthetic.
- Off-white paper background `#F6F3EC`.
- White surfaces and dark ink `#211F1D`.
- Cyan `#0795B9` only for active feedback, selection, insertion rails, and success.
- Lora SemiBold for editorial titles and flow names.
- IBM Plex Sans for UI labels, counts, controls, and email copy.
- Fine neutral borders, 4–8px radii, restrained shadows.
- Avoid generic dashboard styling, excessive pills, gradients, and overcrowding.

## Production constraints

The implementation will use one canonical editable block document between Claude and rendered HTML:

`originalHtml → editableDocument → visual editing → safe compiler → renderedHtml → validation → save/version`

Design controls only for capabilities that can be represented safely by the block schema. Do not expose arbitrary HTML or script editing. Required email structure must visibly communicate its protected state.

## Deliverable

Produce production-ready desktop, tablet, and mobile screens with reusable components, tokens, interaction annotations, responsive behavior, and all states necessary for React implementation in the existing Shopify app.

# Nomi — Spec

One-line promise: "Install it, and your store's email is done."
AI email app embedded in Shopify admin. Merchant installs → AI reads
their store (logo, colors, products, brand voice) → every notification
and marketing email is branded, written, and live in about a minute.
Templates are AI-generated per merchant, not picked from a library.

## The five launch features (v1 — nothing else)

1. Magic setup — AI brands and writes every email from the storefront.
   Done = on install, the app reads the store and produces branded,
   written emails for all core types without manual setup.

2. Order/notification emails — order confirmation, shipping, refunds.
   Sent natively by Shopify from installed templates.
   Done = a real order renders a branded, AI-written confirmation with
   real customer name, real line items, real total.
   [status: order confirmation generating from a live order ✓]
   [status: shipping update generating from a live fulfillment, with real
   tracking info and a real tracking link when Shopify has one ✓ —
   refunds generating from a live refunded order ✓]

3. Abandoned cart recovery — works out of the box.
   Done = a cart with items generates a branded recovery email.
   [status: cart recovery generating from a live abandoned checkout, with
   a real recovery link ✓]

4. One-prompt newsletters — describe a campaign, get a send-ready email.
   Done = free-text prompt ("Diwali sale, 15% off") → branded campaign email.
   [status: dashboard prompt → branded, localized campaign preview ✓ —
   audience selection and campaign delivery remain separate launch work]

5. Review requests — post-delivery follow-up.
   Done = a delivered order generates a branded review-request email.
   [status: generating from a live order once its fulfillment reads
   delivered, with a real link to the product's storefront page when the
   product is published there ✓]

## Sending architecture — DECIDED 2026-08-17
Nomi sends its own emails through Resend. Shopify events enqueue durable,
idempotent jobs; a separately scheduled worker generates the HTML and sends
it, so webhook endpoints return immediately. Current event coverage:
`orders/create`, `fulfillments/create`, `fulfillments/update`,
`refunds/create`, and delayed `checkouts/update` recovery. Checkout updates
reset a one-hour timer, completed orders cancel the pending recovery, and
the worker confirms the checkout still appears in Shopify's abandoned list.

[status: delivery pipeline, retry state, provider adapter, worker endpoint,
and install-time activation built ✓ — production still requires a verified
Resend sender, secrets, a scheduler calling the worker, and a live-store
end-to-end test]

Important launch constraint: Shopify exposes no app API to replace its
native notification templates. Researched (not assumed) per event — see
DECISIONS.md, 2026-08-17: order confirmation and refund confirmation can
never avoid duplicating Shopify's own native email for the same event, on
any plan, with no store setting that fixes it; shipping updates and review
requests are not affected. The dashboard reflects this with two switches,
not one: the main sending toggle covers shipping/cart-recovery/review
sends, and a separate "Order & refund receipts" toggle (default off, one
magenta warning) gates the two duplicate-risk sends independently.

## Explicitly OUT of scope for v1
SMS. Popups. Complex segmentation. Settings sprawl. A browsable library of
generic (non-branded) templates. When tempted to add: "not yet."

## Choice principle
Never remove choice, remove effort. Merchant chooses which look / whether
to go seasonal; Nomi does the work. Options shown are always rendered in
the merchant's own brand, never generic.

## Roadmap (post-v1, not now)
Seasonal auto-refresh (Christmas/BFCM/Diwali "remix"), AI product
recommendations per customer, "Looks" gallery (archetypes in merchant's
brand), revenue attribution dashboard, multi-platform (WooCommerce → Wix
→ BigCommerce; keep engine platform-independent).
